# ТЕХНИЧЕСКИЙ ОТЧЕТ И АРХИТЕКТУРНАЯ СПЕЦИФИКАЦИЯ
## Проект: Сервис синхронного совместного просмотра видео (SyncWatch Party)

---

### 1. ЦЕЛЬ И НАЗНАЧЕНИЕ ПРОЕКТА
**SyncWatch Party** — это полнофункциональный веб-сервис для совместного синхронного просмотра видео с друзьями в реальном времени. Сервис решает проблему рассинхронизации, буферизации у участников с медленным интернетом и обеспечивает интерактивный опыт просмотра с живым чатом, экранными субтитрами Danmaku, плейлистами и потоковой загрузкой файлов без ограничений по размеру.

---

### 2. СТЕК ТЕХНОЛОГИЙ
- **Backend**: Node.js (TypeScript) + Express 4 + Socket.io v4 + Multer (потоковая загрузка на диск).
- **Frontend**: React 19 + TypeScript + Vite + TailwindCSS 4 + Lucide-react (иконки).
- **Стриминг**: HTTP 206 Partial Content (Header: `Range`, `Accept-Ranges`, `Content-Range`, `Content-Length`) с поддержкой чанкового чтения через `fs.createReadStream` и буфером 2MB.
- **Хранение данных**: In-memory Map на сервере (`rooms`) + локальная изолированная файловая система `/storage/rooms/{roomId}/`.

### 5. СЕТЕВОЙ ПРОТОКОЛ (WEBSOCKET BUS)

#### 5.1. Клиент -> Сервер (Client to Server):
- `room:join { roomId, nickname, hostToken }`: вход в комнату (восстановление прав хоста по токену).
- `host:play { currentTime }`: запуск видео хостом.
- `host:pause { currentTime }`: пауза видео хостом.
- `host:seek { targetTime }`: перемотка на конкретную секунду.
- `host:force_play {}`: принудительный запуск в обход отстающих зрителей.
- `host:change_track { trackIndex }`: переключение трека в плейлисте.
- `host:reorder_playlist { newOrderIds }`: сортировка треков.
- `host:delete_track { fileId }`: удаление трека из очереди и с диска.
- `host:transfer_host { newHostUserId }`: передача короны хоста другому пользователю.
- `host:close_room {}`: мгновенное закрытие комнаты и полное удаление файлов с сервера.
- `client:buffering_start {}`: сигнал о буферизации/остановке потока у зрителя.
- `client:buffering_end {}`: сигнал о готовности продолжать воспроизведение.
- `client:progress { currentTime }`: отправка текущей секунды просмотра раз в секунду.
- `chat:send { text }`: отправка сообщения в чат.

#### 5.2. Сервер -> Клиент (Server to Client):
- `room:init_state (RoomState)`: полная синхронизация при подключении/переподключении.
- `room:user_joined (User)`: оповещение о входе нового зрителя.
- `room:user_left { userId, newHostId }`: оповещение о выходе.
- `room:host_changed { hostId }`: смена хоста.
- `sync:play { currentTime, serverTimestamp }`: команда на воспроизведение с расчетом времени.
- `sync:pause { currentTime }`: команда на паузу.
- `sync:seek { targetTime }`: команда на перемотку.
- `sync:buffering_wait { waitingForUsers }`: автопауза из-за лагов/буферизации конкретных людей.
- `sync:buffering_resolved {}`: снятие автопаузы, когда все готовы.
- `playlist:updated { playlist, currentTrackIndex }`: обновление списка видео.
- `users:progress { userId, currentTime }`: обновление таймкодов всех зрителей.
- `chat:message (ChatMessage)`: новое сообщение или системное оповещение.
- `room:closed { reason }`: уведомление о закрытии комнаты и удалении файлов.

### 6. КЛЮЧЕВЫЕ АЛГОРИТМЫ И РЕАЛИЗОВАННЫЕ ТРЕБОВАНИЯ

#### 6.1. Алгоритм плавной подгонки времени (Time Drift Correction):
Каждые 350 мс плеер замеряет дельту: `delta = Math.abs(video.currentTime - expectedTime)`:
- `delta > 1.5 с`: жесткий скачок `video.currentTime = expectedTime; playbackRate = 1.0;`.
- `0.15 с < delta <= 1.5 с`: плавная незаметная догонка:
  - Если отстает: `video.playbackRate = 1.05;` (с бейджем *⚡ 1.05x догонка* у зрителя).
  - Если опережает: `video.playbackRate = 0.95;` (с бейджем *🐢 0.95x подгонка*).
- `delta <= 0.15 с`: идеальный синхрон `video.playbackRate = 1.0;`.

#### 6.2. Умная буферизация (Smart Buffer Barrier) и защита от микро-лагов:
- На видео включен `preload="auto"` для заполнения буфера вперед на 30-50%.
- Обработчики `onWaiting` и `onStalled` проверяют запас буфера (`bufferAhead = buffered.end - currentTime`). Если запас больше 0.5с, видео не дергает автопаузу. Если буфер реально пуст, сервер ставит трансляцию на системную паузу с выводом никнейма отстающего.
- Хост может нажать **«Force Play»** в любой момент, чтобы не ждать отстающего (тот догонит по дрифту).

#### 6.3. Автопауза при проблемах со связью у зрителя:
- При разрыве соединения зрителя во время воспроизведения сервер немедленно ставит всех на паузу и отправляет сообщение: *«⚠️ Пауза: проблемы со связью у [Имя зрителя]»*.

#### 6.4. Окончание видео и поведение плейлиста:
- Если трек не последний: хост автоматически переключает на следующий (`host:change_track`).
- Если видео последнее в плейлисте: плеер автоматически ставит воспроизведение на паузу на финальной секунде, отображает плашку *«Видео завершено. Ожидание следующего видео в плейлисте»* и не сбрасывает плеер в пустоту.
- При выборе любого другого видео таймкод мгновенно сбрасывается в `00:00`.

#### 6.5. Плавная перемотка (Drag & Scrub):
- Полоса воспроизведения поддерживает зажатие и ведение мыши: пользователь зажимает ползунок и плавно перемещает курсор в реальном времени с обновлением кадров и всплывающего таймкода. По отпусканию мыши (`mouseup`) отправляется `host:seek`.

#### 6.6. Потоковая загрузка с отменой (Abort Upload):
- Загрузка видео идет чанками через Multer прямо в файловую систему.
- В интерфейсе отображается процент загрузки и кнопка **«Отменить»** (`xhr.abort()`), которая мгновенно разрывает сетевой запрос и очищает форму.

#### 6.7. Отображение секунд каждого зрителя:
- Во вкладке **«Участники»** в реальном времени пишется точный таймкод каждого пользователя (например `⏱️ 04:12`) со статусом относительно хоста (*«В такт»*, *«Догоняет (+0.4s)»* или *«Отстает на Xs»*).

#### 6.8. Адаптивность для планшетов и мобильных устройств:
- Добавлено определение ориентации экрана (`portrait` / `landscape`).
- **Планшет/телефон в вертикальной ориентации (Portrait)**:
  - Фиксированная компактная шапка (`Navbar` 48px).
  - Полноразмерное видео 16:9 во всю ширину без лишних полей и отступов.
  - Навигационные табы.
  - Окно чата занимает **100% оставшейся высоты экрана** (`flex-1 min-h-0`).
  - Убран лишний баннер «Вы управляете воспроизведением».
  - **Исправлен баг залипания скролла на планшетах**: заменен глобальный `scrollIntoView()` на изолированный `containerRef.current.scrollTop = containerRef.current.scrollHeight`, который срабатывает только если пользователь находился внизу или отправил сообщение сам.
- **Десктоп и планшет в горизонтальной ориентации (Landscape)**:
  - 2 колонки: слева видео 16:9, справа фиксированная панель чата/плейлиста во всю высоту.

#### 6.9. Полное удаление данных при закрытии комнаты:
- Кнопка **«Закрыть комнату»** в шапке хоста вызывает `host:close_room`.
- Сервер выполняет физическое удаление `fs.rmSync('/storage/rooms/{roomId}', { recursive: true, force: true })`, удаляет комнату из памяти и высылает участникам `room:closed`.
- Если все участники выходят из комнаты, сервер мгновенно удаляет все файлы и данные комнаты.

#### 6.10. Устранение пустого пространства на ПК (2K/4K/Широкоформатные экраны):
- Убрано искусственное ограничение `max-w-[1720px] mx-auto`, из-за которого на мониторах 2560x1440 и выше образовывались гигантские черные поля по 400+ пикселей по бокам.
- Добавлен динамический расчет адаптивного соотношения сторон (`aspect-fit` 16:9) на базе `ResizeObserver`: видеоплеер занимает максимально возможное пространство доступной рабочей зоны без деформаций и без внешних черных полей.
- Добавлен **Театральный режим (Theater Mode)**: кнопка сворачивания/разворачивания боковой панели позволяет развернуть кинотеатр во всю ширину экрана на ультрашироких и 2K/4K мониторах.
- В пустое состояние плеера добавлены интерактивные кнопки быстрого старта: загрузка файла и добавление готовых демо-клипов (Big Buck Bunny, Tears of Steel) в 1 клик прямо из центра экрана.

#### 6.11. Комплексная оптимизация загрузки (Resumable Chunked Upload) и раздачи (Zero-Copy Streaming):
- **Чанковая дозагрузка (Resumable Chunked Upload)**:
  - Браузер нарезает видеофайл на чанки по 5 МБ (`File.slice()`) и передает их последовательно через эндпоинт `/api/rooms/:roomId/upload/chunk`.
  - **Пауза и Возобновление**: загрузку можно в любой момент приостановить кнопкой «Пауза» и продолжить кнопкой «Продолжить». Клиент опрашивает сервер через `/api/rooms/:roomId/upload/status/:fileId` и продолжает ровно со смещения последнего подтвержденного байта.
  - **Авто-повтор при сбоях**: при кратковременном обрыве связи клиент автоматически делает до 3 попыток повтора с задержкой 1.5 сек перед выводом ошибки.
  - **Информативная карточка**: отображает имя файла, объем (`450 МБ / 1.4 ГБ`), прогресс-бар, мгновенную скорость (`12.4 МБ/с`) и расчетное время окончания (`~01:15 мин`).
  - **Околонулевой расход RAM сервера (Zero-Copy Disk I/O)**: сервер пишет входящий поток байт каждого чанка напрямую на диск в `.part` файл по смещению через `fs.createWriteStream(..., { start: chunkOffset, flags: 'r+' })`. Данные не аккумулируются в оперативной памяти Node.js (предотвращает падение сервера даже при файлах 10+ ГБ на машинах с 512 МБ ОЗУ).
  - При завершении последнего чанка `.part` атомарно переименовывается в финальный файл (`fs.renameSync`) и регистрируется в плейлисте с мгновенным оповещением всех участников через Socket.io.
  - При отмене загрузки (`/api/rooms/:roomId/upload/cancel/:fileId`) временные `.part` и `.info` файлы немедленно удаляются с диска.
- **Оптимизация HTTP 206 стриминга зрителям**:
  - Буфер чтения `fs.createReadStream` снижен до 128 КБ (`highWaterMark: 128 * 1024`), что устраняет скачки RAM при одновременном просмотре несколькими зрителями.
  - Добавлен хук немедленного освобождения ресурсов `req.on('close', () => fileStream.destroy())`: при перемотке или закрытии вкладки зрителем поток чтения с диска мгновенно уничтожается, исключая утечки памяти и дескрипторов.

### 7. РУКОВОДСТВО ДЛЯ ПРОДОЛЖЕНИЯ РАЗРАБОТКИ В НОВОМ ЧАТЕ
Если разработка будет продолжена в новой сессии:
1. Запуск проекта осуществляется через `npm run dev` (запускает `server.ts` через `tsx`, который поднимает Express, Socket.io и Vite middleware на порту 3000).
2. Стриминг видео реализован в эндпоинте `/api/rooms/:roomId/stream/:fileId`.
3. Все типы и события синхронизированы в `/src/types/watchparty.ts`.
4. Для проверки сборки используются команды `npm run build` и `npm run lint`.
